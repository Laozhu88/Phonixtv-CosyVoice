# 实施方案

## 1. 总体定位

本项目建议采用“`CosyVoice` 推理核心 + 本地工作台 UI + 离线整合包”的方式实施。

这意味着我们不把产品做成依赖复杂云端环境的研发演示工程，而是做成凤凰员工可直接运行的生产工具。

## 2. 推荐技术架构

### 2.1 分层结构

1. 推理层
   - 封装 `CosyVoice` 模型推理
   - 统一文本预处理、发音词典、参数控制

2. 服务层
   - 提供本地 API
   - 负责任务调度、文件管理、日志记录

3. 工作台层
   - 提供给员工使用的图形界面
   - 支持文本编辑、音色选择、试听、导出

4. 打包层
   - 集成 Python 运行时、依赖、模型文件、启动器
   - 输出一键运行的 Windows 整合包

### 2.2 建议技术选型

- TTS 核心：`CosyVoice`
- 后端服务：`Python + FastAPI`
- 前端工作台：`React` 或 `PySide6`
- 本地调用方式：内嵌本地服务或纯桌面模式
- 音频处理：`ffmpeg`
- 打包方式：
  - Python 依赖固化
  - 模型随包分发
  - 使用启动器脚本统一入口

## 3. 为什么建议做本地工作台

对于凤凰内部使用，一键交付和低培训成本比“更炫的技术架构”更重要。本地工作台有以下优势：

- 不依赖外网环境
- 员工安装门槛最低
- 更利于内部分发
- 更容易控制素材和文稿安全

## 4. 建议分阶段推进

### 第一阶段：MVP

- 接入 `CosyVoice`
- 完成单机中文配音
- 实现基础 UI
- 实现导出与日志
- 形成内部试用版

### 第二阶段：凤凰定制版

- 加入新闻播报模板
- 加入发音词典
- 加入品牌化界面
- 形成栏目组可用版本

### 第三阶段：交付增强版

- 完成整合包自动构建
- 支持版本升级机制
- 支持模板分发
- 支持更细粒度的审听与重生成

## 5. 关键难点

- `CosyVoice` 推理环境和依赖整合
- GPU/CPU 兼容策略
- 模型体积较大带来的分发问题
- 不同办公电脑性能差异
- 发音效果与播音风格调优

## 6. 我们的工程策略

建议优先实现“可稳定运行的 Windows 单机版”，再继续优化视觉、流程和高级能力。只要底层推理封装与整合包链路打通，后续功能扩展会非常顺畅。
